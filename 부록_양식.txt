2. 캐릭터 프로필 양식 (4-B에서 사용)
===================================

name_picker.py로 확정한 이름을 아래 표에 배정한다. 빈 칸 0 의무(특히 어미·자칭·생사).

| 이름 | 나이 | **혈연(집안)** | 신분(겉) | 신분(진짜, 있다면) | 역할군 | **공동주역** | 어미 | 자칭 | 생사 | 외형 특징 1개 | 소품 |
|---|---|---|---|---|---|---|---|---|---|---|---|
| | | | | | | | | | | | |

**역할군**은 호칭 검사가 쓰는 값이다. `하인 / 상전 / 며느리 / 바깥사람` 중 하나를 반드시 적는다.

**★ 혈연(집안)** — 2026-08-25 신설. 사고: *"주인공이 임씨 성인데 친 오라비는 서씨입니다"*.
같은 집안이면 같은 기호(A/B/C…)를 적는다. **같은 기호끼리는 성씨가 반드시 같아야 한다.**

```
임분이   62  A   ← 주인공
임돌쇠   67  A   ← 친오라비. 피가 섞였으므로 성씨 '임' 공유
서옥분   35  B   ← 며느리. 혼인으로 들어왔으므로 친정 성 '서' 유지 (A 아님)
삼월이   40  -   ← 하인. 집안 없음
```

- **피가 섞이면 같은 성씨**: 친남매·부모자식·조부모·삼촌·조카
- **혼인으로 맺어지면 각자 성씨**: 부부·며느리·사위·시부모·처가
  (조선은 여자가 혼인해도 친정 성을 그대로 쓴다. 부부가 같은 성이면 오히려 어색하다)
- 이름은 `name_picker.py --family N` 으로 뽑으면 N명이 같은 성씨로 나온다.
- `autofix.check_surnames()`가 자동 검사한다. 혈연 관계어("친오라비·누이·아들…")로
  이어진 두 인물의 성씨가 다르면 FAIL이다.

**★ 나이** — 빈 칸 금지. 숫자로 적는다. 호칭이 여기서 결정된다.
사고: *"할멈인데 애들 부르듯 부르고"*. 나이는 신분과 **별개 축**이다 —
종이어도 예순이면 아이 부르듯 부르지 않는다.

| 나이 | 남이 부르는 말 | 쓰면 안 되는 말 |
|---|---|---|
| ~15세 | 얘야 / 아가 / 이 녀석 / 이름 | 어르신 · 노인장 |
| 16~50세 | 이름 / 자네 / 아씨·서방님(신분따라) | 얘야 · 아가 |
| 51세~ | **할멈 · 어멈 · 노인장 · 어르신 · 영감** | **얘야 · 아가 · 이 녀석 · 꼬마** |

`autofix.check_address()`가 자동 검사한다 — 한 대사에 노인 지칭어와 아이 호칭이 같이 있으면 FAIL.

**같은 나이 칸이 부모-자식·조손 개연성 검사에도 쓰인다 (v12.8 신설).**
`autofix.check_age_arithmetic()` — 부모-자식 관계어("아들·딸·어머니·아버지")가 나오면
나이차 **13세 이상**, 조손 관계어("손자·손녀·할머니·할아버지")면 **26세 이상**을 요구한다.
`AGES = {"이름": 나이, ...}` 딕셔너리로 넘겨야 검사한다 — 본문에서 나이를 추측하지 않는다.
이전엔 "인물 나이 산수"가 최종 게이트의 수동 확인 항목이었다. 절약모드에서는 사람이 안 보므로
검사가 새는 구조였다 — 2026-08-23 호칭 사고와 같은 패턴이라 자동화했다.

**공동주역**은 이미지 프로젝트가 캐릭터 시트 순서를 정하는 값이다(2026-08-25 신설, v7에서 용도 조정).
정확히 두 인물(또는 주인공 성별만 있으면 한 인물)에게만 `여자주역` / `남자주역`을 적는다 —
축A는 주인공(아이)+반대 성별 공동 주역, 축C는 본처(또는 축 중심 여성)+남편. 나머지는 빈 칸으로 둔다.
캐릭터 시트 자체는 여전히 등장 빈도 상위 4~6명(축C는 6~9명) 전부 만든다 — 이 칸은
"누가 시트 맨 앞에 나오는지"만 정한다. 이 둘 외의 인물이 시트에서 빠지는 게 아니다.
(하인 = 유모·여종·머슴·몸종·침모·찬모·어멈 / 상전 = 대감·마님·아씨·도련님)
역할군이 빈 칸이면 autofix.check_address()가 그 인물의 대사를 검사하지 못한다.

- 등장인물 수: 축A 4~12명(평균 7명) / 축C 6~9명 — 집필규칙_통합.md VI장 실측치 기준.
- 신분 증표: 집필규칙_통합.md VII장 "신분 증표 풀" 중 2가지 이상 조합(4-4에서 강제 검증). 문서·기물 같은 물증형이 1순위.
- (축C 전용) 아래 3항목을 팩트시트에 반드시 채운다: 모욕의 순간(무슨 말을 들었고 무엇을 빼앗겼는지) / 경과 기간(하루아침에·석 달 뒤·한 해 뒤) / 역전 도달점(어느 자리까지 올라가는지).

|---|---|---|
| 주인공(선량) | ~하옵니다/~이옵니다 | 또박또박, 담담, 짧은 문장 |
| 악역 | ~하시오/~란 말이오 | 고압적, 비꼼, 협박 |

| 구경꾼 | ~대/~래 | 수군거림, 감탄 |
| 가족 갈등 인물 | 반말/존대 오감 | 감정 폭발, 진심 못 함 |

[3-2. ★ 인물 × 인물 호칭표 — 챕터 집필 전에 반드시 채운다]

등장인물 전원에 대해 **"이 사람이 저 사람을 부르는 말"**을 한 칸도 비우지 않고 적는다.

| 말하는 사람 ↓ / 듣는 사람 → | (주인공) | (인물2) | (인물3) | (인물4) | ... |
|---|---|---|---|---|---|
| (주인공) | — | | | | |
| (인물2) | | — | | | |
| (인물3) | | | — | | |
| (인물4) | | | | — | |

[3-2-1. 인물 소개 문장 — 자동 검사가 걸리게 하는 조건]

호칭 검사기(autofix.infer_cast)는 대본 본문에서 이름 → 역할군을 스스로 뽑는다.
아래 세 꼴 중 하나만 대본 어딘가에 한 번 있으면 그 인물은 전 챕터에서 검사가 걸린다.

  · 유모 삼월이가 …            (역할 + 이름)
  · 삼월이라는 여종             (이름 + 라는 + 역할)
  · 삼월이는 이 집 유모였습니다 (이름 + … + 역할 + 서술어)

이름만 나오고 신분을 끝까지 안 밝히는 인물은 검사에서 빠진다. 인물마다 한 번씩은 넣는다.
신분이 바뀌는 인물(종 → 마님)은 두 역할이 다 잡히므로 '신분변동'으로 표시되고
호칭 검사를 걸지 않는다 — 3-4표에 적어 두면 사람이 그 구간만 보면 된다.

[3-3. 자칭표]

| 인물 | 상대 | 자칭 |
|---|---|---|
| | | |

하인은 상전에게 `소인 / 쇤네 / 소녀`. `나 / 내가`는 오류다.

[3-4. 호칭이 바뀌는 지점]

신분이 바뀌면 호칭도 바뀐다. 바뀌는 챕터와 대사를 미리 정해 둔다.

| 인물 | 바뀌기 전 | 바뀐 뒤 | 바뀌는 챕터 | 그 장면 대사 |
|---|---|---|---|---|
| | | | | |

[3-5. 하인이 절대 쓸 수 없는 말 — 하드 금지]

며느리 · 며늘 · 새아기 · 사위 · 올케 · 동서 · 형수 · 제수 · 시누이 · 처남 · 처제 ·
장인 · 장모 · 아버님 · 어머님 · 형님 · 누님 · 오라버니 · 서방님(제 남편이 아닐 때) ·
자네 · 이보게 · 여보게 · 그대 · 너

→ `아씨 / 마님 / 작은마님 / 큰마님 / 대감마님 / 나리 / 도련님 / 아기씨` 로 바꾼다.

[3-6. 비하 호칭]

비하 호칭("~년"/"이놈" 등)은 전체 대본에서 최대 2회. 그 이상은 아래로 대체:

5. 반전·발단 자가검증 5문항 (4-C에서 사용)
===================================

발단 1회 + 반전 6개 각각에 이 5문항을 적용한다. 하나라도 NO면 폐기·재설계.

1. **동기 충분성** — 악역·인물의 동기가 그 행동을 선택할 만큼 충분한가?
2. **인물 일관성** — 주인공의 약점·강점이 사건 발생 이유와 일관되는가?
3. **시공간 가능성** — 시간·공간 제약 안에서 그 행동이 실제로 가능한가?
4. **인과 방향성** — 원인→결과 순서가 뒤집혀 있지 않은가? (예: "맹인이라 반박 못 한다"처럼 결과를 원인처럼 쓰지 않았는가)
5. **예측 가능성** — 앞서 나온 단서만으로 이 반전을 완전히 예측할 수 있는가? (너무 뻔하면 NO)

4가지 카테고리(신분/능력/관계/초자연) 분산 검증: 반전 6개 중 한 카테고리가 4개 이상이면 ❌ → 재설계.

표 형식으로 고정:
- 인물명 | 나이 · 신분(겉) · 신분(진짜, 있다면) · 외형 특징 1개 · 소품

```python
from autofix import timetable
tt, v = timetable([("사연의 시작", CH1), ("쫓겨나던 날", CH2), ...])
print(tt, v)      # v["유튜브_규칙_통과"] 가 True 여야 쓴다
```

- 유튜브 챕터 규칙: 첫 줄 `0:00` / 최소 3개 / 각 구간 10초 이상. 하나라도 어기면 챕터가 안 붙는다.
  `timetable()`이 세 가지를 자동 검사한다.
- 챕터 제목: 스포일러 금지. 장면 이름으로 짓는다(`쫓겨나던 날` / `석 달 뒤`). 6~12개.
- 낭독 속도 기본 378자/분은 브루 '자비 왕후' 실측치다. 목소리·속도를 바꾸면
  `(공백 제외 자수 ÷ 실제 분수)`로 다시 구해 `timetable(..., cpm=새값)`으로 넘긴다.

-----------------------------------
12-4. 해시태그 · 제목 꼬리 (v12.12 신설 — 시장 40편 실측)
-----------------------------------

**해시태그 위치는 자유다.** 실측 3편이 전부 다른 자리에 뒀다
(제목 꼬리 / 설명 최상단 / 설명 하단). 성적과 무관하다. 하나만 고른다.

**개수: 10~13개.** 아래 [고정 8개] + [이번 화 성격 2~5개].

```
[고정 8개 — 매 편 그대로]
#야담 #옛날이야기 #민담 #설화 #전설 #오디오북 #수면동화 #조선야담

[성격 태그 — 이번 화에 맞는 것으로 2~5개 고른다]
축A(신분·정체 반전) 계열 : #권선징악 #인과응포 #통쾌한이야기 #사이다야담 #역전야담
축C(팔자역전) 계열       : #감동사연 #인생역전 #팔자역전 #효도라디오 #시니어야담
```
※ 오타 주의 — `#인과응보`가 맞다. 위 목록은 실측에서 본 표기를 그대로 옮긴 것이 아니라
  정리한 것이다. 실제로 쓸 때 맞춤법을 확인한다.

**제목 꼬리 (파이프 나열)** — 실측 40편 다수가 제목 뒤에 이걸 붙인다.
```
| 야담 | 옛날이야기 | 민담 | 수면동화 | 오디오북
```
- 제목 본문이 길면 꼬리를 3개로 줄인다. **본문이 잘리면 안 된다** — 꼬리보다 본문이 우선이다.
- 제목 꼬리에 파이프를 쓰면 설명란 해시태그는 하단에 두고, 제목에 `#`를 쓰면 설명란
  최상단에 4개만 둔다. **둘 다 하지 않는다** — 실측에서 겹쳐 쓴 편이 없다.

**금지:** 조회수·구독자를 유인하는 태그(#구독 #떡상 #조회수), 남의 채널 이름,
내용과 무관한 인기 태그. 유튜브 스팸 정책 위반이다.

부록 A~E — 산출물 형식 보충 (기존 버전 보존)
===================================

이전 부록_양식.md에 있던 5개 항목. 위 11종과 별개로, 최종 출력 파일 자체의 물리적 형식·파일명 규칙을 다룬다.

--- A. 풀대본(script_full) ---
- 메타 정보(헤더·구분선·글자수 표기·이모지) 전부 금지. 순수 내레이션 텍스트만.
- 단락 구분은 줄바꿈만 사용.
- 인트로 구간(6문장)만 맨 앞과 "자, 그럼 시작합니다." 직후에 -- 표시로 감싸 본편과 구분.
- 챕터 경계는 텍스트 안에 표기하지 않음(완성 영상에는 챕터 구분이 드러나지 않으므로).
- 대사는 큰따옴표로 감싼다.

--- B. 40씬 분할본(script_scenes) — 「브루 자동매칭」 앱 입력 ---
- **7단계에서 자동 생성해 사용자에게 전달한다.** `autofix.split_scenes(merged, 40)`.
- **용도: 「브루 자동매칭」 앱(v2.5+)에 그대로 넣는 대본 파일이다.**
  앱은 이 파일 + `.vrew`(TTS 완료본) + 이미지 폴더(`001.png`, `002.png`…)를 받아
  자막과 대본을 대조해 각 [img:NNN] 구간에 이미지를 자동 배치한다.
- 형식 (앱 사용법.txt "대본 태그 예시" 규격, 2026-08-25 정렬):
```
[img:001]
첫 장면 나레이션...
두 번째 줄...

[img:002]
다음 장면 나레이션...
```
  · 태그는 **[img:001] 3자리 제로패딩**. (v12.5까지 `[img:1]`로 뽑아 앱에 못 넣었다)
  · 태그는 단독 줄, 다음 줄부터 그 구간 원문. 블록 사이 빈 줄 1칸.
  · 번호는 1부터 빠짐없이 연속. 빈 블록(태그 뒤 본문 없음) 금지 — 앱이 누락으로 검출한다.
- 본문(인트로 제외)만 대상. 문장 끝에서만 자름. 씬 크기는 누적 글자수 기준으로 고르게 나눈다.
- 태그를 전부 제거하고 이어붙인 텍스트는 script_full 본문과 글자 단위 100% 일치해야 함
  → `autofix.verify_scenes()`가 검산한다. **`앱_규격_통과`가 True여야 저장한다.**
- `짧은_시작문장`은 참고치다 — 태그 직후 문장이 12자 미만이면 앱에서 [추정](빨강)으로
  잡힐 수 있다. 앱은 12자 이상 일치를 [정확] 매칭으로 친다. 다만 이걸 맞추려고
  **본문 글자를 고치면 안 된다** — 원문 일치가 깨진다. 씬 경계 조정으로만 해결한다.
- Google Flow 이미지 프롬프트 도구는 자체 PHASE 2 코드로 독립 분할하므로 이 파일을 입력으로
  요구하지 않는다. 이 파일의 주 용도는 브루 자동매칭이다.

--- C. 파일명 규칙 ---
- 이번 화 결과물: {화번호}_{제목슬러그}_{산출물종류}.{확장자} (예: 037_흰뱀편_script_full.txt)
