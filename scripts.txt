scripts.txt — 화별 누적 로그

완성된 화가 나올 때마다 아래 표에 한 줄씩 추가한다(append-only, 기존 줄 수정 금지).
name_bank·motif_bank의 차단 목록이 이 표를 근거로 갱신된다 — 이름·모티프·반전카테고리·신분증표 유형이
최근 몇 화 안에 반복되지 않았는지 이 표에서 확인한다.

===================================
표 형식
===================================

화번호 | 제목 | 축(A:A형 / C:C형) | S후크 | V축 6값 | 반전재료 행 | 훅 문형(H1~H5) | 신분증표 유형 | 등장인물 이름 | 글자수 | 완성일

001 | 왕손의딸 | A | S1 | V1 열두 살 소녀 / V2 소금장수 딸 / V3 구해지는 쪽이 귀인 / V4 반쪽 신물 / V5 십 년 뒤 / V6 은인의 가문 | A3, B7 | H1 | 물증형(반쪽 신물)+신체표식(반달점) | 월옥, 한훈식, 강화옥, 조산빈, 이규빈, 최돌복 | 30608 | 2026-08-30

===================================
열 작성 기준
===================================

- 축: A(축A형 — 왕실·관아 신분정체 반전) / C(축C형 — 반가 처첩·팔자역전). v11에서 축B는 폐지됐다.
- **S후크 (v12.12 신설)**: 모티프_뱅크.txt S열에서 이번 화 주축으로 쓴 후크 번호(예: "S1").
  최근 5행 안에서 **2연속 동일 금지** 판정에 쓴다. 3편 이상 띄우면 재사용 자유.
  **★ 반드시 `S1`~`S16` 번호로 적는다 (v12.13).** 뒤에 이름을 붙이는 건 자유다(`S1 쫓기는 귀인 구원`).
  **A3·E5 같은 플롯 유형이나 그 설명("신분 은닉·정변 생존자")을 이 칸에 적으면 안 된다** —
  그건 `반전재료` 칸이다. 실제로 001화가 이렇게 잘못 적혀 중복 회피가 통째로 무력화됐다.
- **V축 6값 (v12.12 신설)**: 그 후크를 어떻게 굴렸는지 6칸을 짧게.
  예: `V1 열한살소녀 / V2 소금장수딸 / V3 구해지는쪽 / V4 밥한상 / V5 열흘뒤 / V6 자식`
  같은 S후크를 다시 쓸 때 **V축 3개 이상**이 직전과 달라야 한다는 판정의 근거다.
  이 칸을 비우면 다음 화가 같은 후크를 같은 값으로 다시 뽑는다.
  **★ 값은 모티프_뱅크 V축 표에 있는 것으로 적는다 (v12.13).** 자유 서술로 적으면
  비교가 안 된다. 표에 없는 상황이면 표에 값을 먼저 추가한다.

**저장 전 기계 검사 (v12.13):**
```python
from autofix import check_log_line
print(check_log_line(이번_화_로그_한_줄))   # 통과 가 True 여야 이 표에 넣는다
```
- 반전재료 행: 모티프_뱅크.txt A·B·E·D열에서 이번 화에 붙인 행 번호(예: "A7, B6" / "E5, D2").
  후크를 고른 **다음에** 고른다.
- 훅 문형: 오프닝에 쓴 문형 번호 H1~H5 (모티프_뱅크.txt 하단). 최근 2편과 달라야 한다.
  H5는 제목 첫머리를 큰따옴표 대사로 여는 형태다.
- 신분증표 유형: 집필규칙_통합.md VII장 신분 증표 풀 중 사용한 것(연속 3편 이상 동일 유형 금지 확인용).
- 등장인물 이름: name_bank 차단 목록에 그대로 추가할 이름들.

===================================
사용 규칙
===================================

새 화 기획 시작 전, 이 표의 최근 5~10행을 먼저 훑어 축·S후크·V축·반전재료·훅 문형·신분증표 유형의 다양성을 확인한다.
같은 값이 3회 연속 이어졌다면 이번 화는 다른 값을 우선 배정한다.

**S후크와 훅 문형은 기준이 더 빡빡하다 (v12.12).**
- S후크: 최근 5행 안에서 **2연속 동일 금지**. 3편 이상 띄우면 재사용해도 된다.
  단 재사용할 때는 **V축 6값 중 3개 이상**이 직전 사용분과 달라야 한다.
  (시장 1위작 채널도 같은 후크를 물건과 햇수만 바꿔 두 번 냈다 — 재사용 자체는 전략이다)
- 훅 문형: 2회 연속에서 이미 교체한다. 오프닝은 시청자가 가장 먼저 듣는 부분이라
  반복이 가장 빨리 티가 난다.

===================================
검증 코드는 autofix.py 하나뿐이다 (v11에서 정리)

===================================

예전에는 이 파일 안에도 check_chapter() / remove_meta() / CHAPTER_THRESHOLDS_N 구현이 통째로 들어 있었다.
autofix.py에도 같은 함수가 있어서 **같은 코드가 두 벌** 돌아다녔고, 이 파일 쪽이 낡은 채로 남아 있었다.

낡은 쪽에 있던 문제 2가지:
- 챕터 임계값이 5/7/9(구 25,000·35,000·46,000자) 기준 — v11의 5/6/7(24,000·27,000·34,000자)과 불일치
- 비하 호칭을 `"년"` 한 글자로 세고 있었음 — 인물 이름이 "서분년"이면 197건 오탐이 나서
  최종 게이트가 막히던 그 버그. autofix.py는 2026-08-05에 이미 고쳤는데 이 파일만 안 고쳐져 있었다.

**v11부터 검증 코드는 autofix.py 한 곳에만 둔다.** 이 파일은 화별 로그만 담는다.

야담 대본 지침.txt(v11_main) 7단계에서 아래처럼 부른다:

```python
from autofix import autofix, check_final

merged = autofix(open(PATH, encoding='utf-8').read())
result = check_final(merged, target=TARGET, total_chapters=N)
```

check_final()이 내부에서 check_formula()(성공공식 A군 7항목)까지 자동으로 돌린다.
정규식으로 판별 못 하는 항목(어미 인접반복·동일단어·인접동일대사·호칭사전 위반·이탈방어훅·인물 나이 표기·
주제문 회수)은 결과 dict의 `_수동확인_필요` 목록에 담겨 나오므로, 그건 AI가 직접 읽어 확인한다.
